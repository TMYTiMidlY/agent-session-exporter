# ADR 0001：产品范围与"归档 ≠ 恢复"

## 状态

已接受。包与命令入口见 [ADR 0002](0002-single-package-asmgr-distribution.md)，归档数据模型与保真度见 [ADR 0003](0003-archive-reconstruction-fidelity.md)。

## 背景

项目同时面对两类不同目标：一类是读取、检索和展示历史会话，另一类是把会话迁移到仍可由原 agent 继续使用的状态。两者使用的输入、允许的写入和保真度要求不同，不能共用一个含糊的"恢复"概念。

## 决策

`agent-session-manager` 将能力分为归档与恢复两侧：

- **归档**读取本地 agent 状态、导入快照、显式文件或缓存，将它们转换成可检索和渲染的会话表示。归档不会修改 agent 的 live 状态；只有用户显式提供远端来源或执行备份时才联网。
- **恢复**重建原 agent 能继续使用的原生会话状态。报告、规范化时间线和只读缓存都不是可续聊状态，不能作为恢复结果冒充原生会话。

归档产生的报告允许为阅读目的重排、省略或扩展信息，但所有损失都必须显式标记。恢复则以原生状态为准，只能修改迁移所必需的功能字段，不改写作为历史事实的会话正文。

项目只向自身托管目录、用户指定的输出位置或明确的恢复目标写入；不会把导入、缓存恢复或报告生成隐式写回 live agent 目录。任何可能覆盖原生状态的恢复操作都必须单独设计校验、冲突处理和回滚边界。

备份是归档和未来恢复可以使用的数据来源，不是产品身份，也不改变归档与恢复的边界。

## 后果

- 新增数据源时，只要遵守只读 live 状态、显式联网和显式损失的边界，就可以接入同一归档链路。
- 缓存恢复与原生会话恢复必须使用不同术语和安全约束。
- 原生恢复尚未实现；实现前不得把归档报告或缓存描述成可续聊恢复。
