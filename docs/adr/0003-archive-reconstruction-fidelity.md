# ADR 0003：归档数据的规范化与保真度

## 状态

已接受。归档与恢复的边界见 [ADR 0001](0001-scope-archive-and-restore.md)。

## 背景

不同 agent 和分享来源使用不同的持久化结构，有些来源还会隐藏结果、遗漏附件或只保留文本。如果渲染器直接理解每一种原始格式，数据源差异会扩散到搜索、HTML 和 Markdown，并让信息损失难以识别。

## 决策

所有归档来源都经过适配器转换为统一的 `ParsedSession` 与规范化时间线，搜索和渲染只依赖这一模型。

- 对远端导入来源优先保存带版本的原始快照，再在读取时规范化；这样解析器改进后可以重新解释既有归档。
- 适配器必须区分已处理、有意忽略和未知输入，让格式漂移显式出现，不能把未知记录静默当成空内容。
- 来源缺失、隐藏或未归档的内容必须通过 `lossy` 与具体警告暴露。占位符、推断值和渲染近似不能被描述成原始内容。
- 只有存在可验证的一一关系时才合并调用与结果；关联不明确时保留独立条目或未完成状态，不跨轮次猜测。
- 规范化时间线可以增加有助于阅读的结构，也可以采用独立渲染实现，但不声称与上游 live 界面逐字节等价。

## 后果

- 每个新适配器都要定义来源保真度、未知输入策略和可验证的关联规则。
- HTML、Markdown 与文本输出共享相同的损失警告和规范化结果。
- 具体事件映射、存储路径、命令和格式漂移检查属于当前实现说明，放在 README 和测试中维护。
